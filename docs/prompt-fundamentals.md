## プロンプトとは

プロンプトとは、AI（特に大規模言語モデル）に対して与える指示や質問のことです。プロンプトの質によって、AIからの回答の精度、関連性、有用性が大きく変わります。

### なぜプロンプトが重要なのか

- AIは与えられた情報に基づいて応答を生成する
- 曖昧な指示は曖昧な回答につながる
- 明確で具体的な指示は、より正確な結果を生む

## 効果的なプロンプトの基本原則

### 1. 明確さ（Clarity）

何を求めているのかを明確に伝えましょう。

**悪い例：**
```
文章を書いて
```

**良い例：**
```
新入社員向けのビジネスメールの書き方について、
300文字程度の説明文を書いてください。
```

### 2. 具体性（Specificity）

具体的な条件や制約を示すことで、期待する結果に近づきます。

**悪い例：**
```
プログラムを作って
```

**良い例：**
```
Pythonで、CSVファイルを読み込み、
売上金額の合計を計算するプログラムを作成してください。
入力ファイル名は「sales.csv」とし、
「金額」という列の合計を出力してください。
```

### 3. 文脈の提供（Context）

背景情報を提供することで、より適切な回答が得られます。

**悪い例：**
```
このエラーを直して
```

**良い例：**
```
Node.js 18でExpressを使ったWebサーバーを開発しています。
以下のエラーが発生しました：
「TypeError: Cannot read property 'id' of undefined」
このエラーはユーザーログイン時に発生します。
原因と解決方法を教えてください。
```

### 4. 出力形式の指定（Format）

期待する出力形式を明示することで、使いやすい結果が得られます。

```
以下の項目について、表形式でまとめてください：
- 項目名
- 説明
- 優先度（高/中/低）
```

## プロンプトの構成要素

効果的なプロンプトは、以下の要素で構成されます：

| 要素 | 説明 | 例 |
|------|------|-----|
| **役割（Role）** | AIに期待する立場や専門性 | 「あなたはシニアエンジニアです」 |
| **タスク（Task）** | 実行してほしい具体的な作業 | 「コードをレビューしてください」 |
| **文脈（Context）** | 背景情報や状況説明 | 「本番環境で動作する重要なコードです」 |
| **制約（Constraints）** | 守るべき条件や制限 | 「100行以内で」「日本語で」 |
| **例（Examples）** | 期待する出力の参考例 | 「例：○○のような形式で」 |
| **出力形式（Format）** | 回答の形式や構造 | 「箇条書きで」「JSON形式で」 |

## プロンプトエンジニアリングのテクニック

### 1. ゼロショット・プロンプティング

例を与えずに直接指示する最もシンプルな方法です。

```
「人工知能」を英語に翻訳してください。
```

### 2. フューショット・プロンプティング

いくつかの例を示してからタスクを依頼する方法です。

```
以下の形式で感情を分類してください：

入力：「今日は最高の一日だった！」
出力：ポジティブ

入力：「電車が遅れて会議に遅刻した」
出力：ネガティブ

入力：「明日は雨かもしれない」
出力：
```

### 3. 思考の連鎖（Chain of Thought）

段階的に考えるよう促すことで、複雑な問題を解決します。

```
以下の問題を、ステップバイステップで考えて解いてください：

太郎は1000円持っています。
250円のパンを2つ買いました。
残りのお金で150円のジュースは何本買えますか？
```

### 4. 役割設定（Role Playing）

特定の専門家として回答するよう指示します。

```
あなたは10年の経験を持つセキュリティエンジニアです。
以下のコードのセキュリティ上の問題点を指摘してください。
```

### 5. 制約条件の明示

明確な制約を設けることで、回答の範囲を絞り込みます。

```
以下の条件で説明してください：
- 専門用語を使わない
- 小学生にもわかる言葉で
- 3文以内で
```

## よくある間違いと改善方法

### 間違い1：曖昧すぎる指示

**Before:**
```
良いコードを書いて
```

**After:**
```
ユーザー登録フォームのバリデーション関数を
TypeScriptで書いてください。
検証項目：メールアドレス形式、パスワード8文字以上
```

### 間違い2：情報の不足

**Before:**
```
このバグを修正して
```

**After:**
```
以下のReactコンポーネントで、
ボタンをクリックしてもカウントが増えないバグがあります。
原因を特定し、修正したコードを提示してください。

[コードを貼り付け]
```

### 間違い3：複数のタスクを一度に依頼

**Before:**
```
このコードをレビューして、テストを書いて、
ドキュメントも作成して、
リファクタリングもしてください。
```

**After:**
```
まず、このコードのレビューをお願いします。
特に以下の観点でフィードバックをください：
1. 可読性
2. パフォーマンス
3. エラーハンドリング
```

## 実践例

### 例1：技術文書の作成

```
対象読者：JavaScriptの基礎を理解している開発者
目的：React Hooksの基本的な使い方を説明する
形式：チュートリアル形式（コード例を含む）
文量：1000文字程度
トーン：親しみやすく、技術的に正確に

useState と useEffect の基本的な使い方について
チュートリアル記事を書いてください。
```

### 例2：コードレビュー依頼

```
役割：シニアPythonエンジニアとして
タスク：以下のコードをレビュー
観点：
- PEP 8準拠
- 型ヒントの適切さ
- エラーハンドリング
- パフォーマンス

指摘は「重要度（高/中/低）」「該当行」「問題点」「改善案」
の形式で記載してください。

[コードを貼り付け]
```

### 例3：データ分析

```
以下の売上データを分析してください。

データ：[データを貼り付け]

分析項目：
1. 月別売上推移
2. 商品カテゴリ別の売上構成比
3. 前年同期比較

出力形式：
- 各項目の分析結果を箇条書きで
- 重要な発見を3点にまとめる
- 改善提案を含める
```

## まとめ

効果的なプロンプトを作成するためのポイント：

1. **明確に** - 曖昧さを排除する
2. **具体的に** - 詳細な条件を指定する
3. **文脈を提供** - 必要な背景情報を含める
4. **形式を指定** - 期待する出力形式を明示する
5. **段階的に** - 複雑なタスクは分割する

プロンプトは「AIへの仕様書」と考えましょう。良い仕様書がなければ良い成果物は生まれません。練習を重ねて、効果的なプロンプトの書き方を身につけていきましょう。
